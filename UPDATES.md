# Release and automatic updates

OrangeHub uses the Tauri updater plugin. GitHub Releases host the Windows installers and the signed `latest.json` update manifest. The release workflow is `.github/workflows/release.yml`.

## GitHub configuration

The public update endpoint and product-page download link target `djteang/OrangeHub`. Keep the repository public so installed clients and the product page can read its Releases.

The workflow reads these repository Actions secrets:

- `TAURI_SIGNING_PRIVATE_KEY`: contents of the private key generated by Tauri. This repository already has this secret configured.
- `TAURI_SIGNING_PRIVATE_KEY_PASSWORD`: only needed if the private key was created with a password; otherwise leave it empty.

The matching public key is stored in `src-tauri/tauri.conf.json`. Never commit the private key.

## Publishing a release

1. Set the same new version in `package.json`, `src-tauri/Cargo.toml`, and `src-tauri/tauri.conf.json`.
2. Commit and push the version change to `main`.
3. Create and push a matching version tag. For example, for version `0.1.1`:

   ```powershell
   git tag v0.1.1
   git push origin v0.1.1
   ```

The workflow checks that the tag and Rust/Tauri versions match, then builds and publishes `OrangeHub-Setup.exe`, the MSI installer, updater signatures, and `latest.json`. The Windows product page links to `OrangeHub-Setup.exe`. In the desktop client, **Check for updates** verifies the manifest signature before asking to download and install a newer version.
